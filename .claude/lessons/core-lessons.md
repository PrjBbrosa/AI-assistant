## 2026-04-16 近似几何公式应取保守下限而非平均值

- **错误**：DIN 5480 近似公式先按 catalog 中 m=1.25 单一样本反推出 `h_w=0.9·m`，但 catalog 里 m=2/z=8 实测 h_w/m=0.525，对小齿数大模数条目近似高估 71%，导致 p_flank 低估 42%，"通过"的结果可能实际 FAIL（非保守事故）。
- **正确做法**：跨规格工程近似必须取参数全域的**保守下限**（catalog 最苛刻条目 h_w/m=0.5），并在计算 `messages` 里明确标注"近似可能低估/高估的方向与幅度"。切勿用单一样本验证系数。
- **原因**：校核公式的"绿灯"只有在保守方向才能作为工程决策依据；非保守近似比拓扑错误更危险（拓扑错误用户能察觉，非保守误差用户看不见）。

## 2026-04-16 默认值变更是 API 破坏性改动，需 messages 提示

- **错误**：`k_alpha` 默认值从 1.0 改到 1.3 对 UI 一致，但对外部调用方（未显式传 k_alpha 的 JSON）是破坏性变更，结果会突然变严 30%。
- **正确做法**：calculator 入口检测到默认兜底时，在 `messages` 里显式告知 "采用默认 k_alpha=1.3（保守上限）"；并在 docstring 顶部标明破坏性变更日期。
- **原因**：计算库一旦被外部（脚本/批处理）调用，静默改默认值会让回归偏差无法溯源。

## 2026-04-18 禁止 Unicode 智能引号 U+201C/U+201D（从 CLAUDE.md 迁移）

- **错误**：在含中文上下文的 Python 字符串中粘贴，导致 `"` `"` (U+201C/U+201D) 进入代码，出现以下两类症状：(1) 某些环境下 Python 直接 SyntaxError；(2) 更危险——字符串比较静默失败（"测试案例" != "测试案例"），if/dict/枚举分支全部走错，pytest 全绿但运行时行为错。
- **正确做法**：calculator/InputError/messages 中一律使用 ASCII `"` 和 `'`；Python 源文件提交前可 `grep -P "[\u201c\u201d]"` 扫描一次。若必须引述中文术语，用全角书名号 `「」` 或直接括号。禁止从 Markdown/文档/微信对话直接粘贴含引号的文案。
- **原因**：U+201C/U+201D 与 ASCII `"` 在终端、VSCode、diff 工具里视觉几乎不可区分，bug 会以"字符串为何不相等"的诡异形式暴露，排查成本可达小时级。

## 2026-04-18 校核未覆盖项必须显式"未校核"，严禁伪绿灯（从 CLAUDE.md 迁移）

- **错误**：轴向受力螺纹连接早期实现中，若未提供 `thread_strip.m_eff`（螺纹脱扣校核所需数据），该项被静默跳过，但 `overall_status` 仍汇总为 PASS；用户看到绿灯以为整体通过，实际螺纹脱扣从未被校核。
- **正确做法**：任何可选/条件性校核项，**未执行不得计入 overall**——必须显式返回 `status="not_checked"`，并把 `overall_status` 置为 `"incomplete"`（不是 `"pass"` 也不是 `"fail"`）。UI 层对应显示"未校核"徽章（非绿、非红，建议用黄/灰）。core 的 `messages` 追加一条"XXX 校核未执行：缺少 YYY 参数"的提示。
- **原因**：工程校核的 PASS 是决策依据；"没算"被包装成"通过"属于最危险的非保守失真——用户即使仔细看结果页也察觉不到遗漏。`incomplete` 是唯一能同时避免"伪绿灯"和"伪红灯"的状态。

## 2026-04-18 强度/疲劳判据禁止人为下限（从 CLAUDE.md 迁移）

- **错误**：早期 Goodman 疲劳折减里给 `σ_m ≥ 0.9·Rp0.2` 加了"保护下限"，试图避免安全系数算出负数或接近零的极端值；结果高平均应力工况下疲劳校核被人为抬过判据线，拿到 PASS。
- **正确做法**：强度/疲劳判据公式按标准（VDI 2230 / ISO 898-1 / DIN 743 等）实施到底，**不加任何"避免难看数字"的人为钳位**。σ_m ≥ 0.9·Rp0.2 这类极端工况直接判 FAIL 或抛 InputError；若确有保守保护需求，必须在 docstring 和 `warnings` 里显式标注，且不得影响 PASS/FAIL 判定。
- **原因**：任何人为钳位都破坏工程可追溯性，且会让"边界工况"伪装成"正常工况"。标准算出来的负安全系数就是要让用户看见——那正是标准设计时希望触发的告警信号。

## 2026-05-02 退化路径必须写进 core warning 而不是只靠 UI 猜

- **错误**：缓冲块吸能模块触底时，`time_response` 实际只返回压缩段、回弹段未建模，但初版 warning 只写了“峰值力未知、回弹能量仅供参考”，没有明确暴露“触底后时域响应未建模”。
- **正确做法**：core 只要进入退化路径（触底、不可判定、只返回部分结果、数值反推失败），warning 必须逐字说明“哪些结果不可判定 / 哪些段未建模 / 哪些值仅供参考”，并用测试断言关键文案。
- **原因**：UI 和报告只是消费 core 事实，不能靠页面文案补猜 core 的隐藏状态。工程用户看到响应曲线时，需要从 core 结果本身知道它是否完整，否则会把压缩段-only 曲线误读为完整接触过程。

## 2026-07-02 判定链与展示链必须做同点一致性断言

- **错误**：worm 判定用接触应力与曲线展示用应力在同一物理点相差 2.5 倍（判定用乐观模型）；interference 空心轴只判定配合面漏掉更危险的内孔壁。
- **正确做法**：同一物理量存在两条实现路径（判定 vs 展示/辅助）时，必须加一条一致性回归测试（assertAlmostEqual 比值约等于 1 或明确记录差异原因），且判定路径取保守侧。
- **原因**：“算了两遍”时更弱的那份往往落在门槛判定上，静态 review 与常规测试都不覆盖这种分叉。
