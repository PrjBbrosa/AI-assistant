# Local Engineering Assistant 全软件质量 Review

- 日期：2026-08-23
- 范围：计算核心、输入与自动化、UI/视觉、运行性能、架构、鲁棒性、测试、导出、文档与发布工程
- 评审模式：只读。除本报告、配套 spec 和 plan 外，没有修改产品源码
- 总结结论：**NEEDS REVISION / 暂不建议将绿色 PASS 作为可签发工程结论**

## 1. 执行摘要

软件已经越过“原型”阶段：7 个计算模块具备统一桌面壳、输入保存/加载、计算结果、报告导出和较完整的回归测试；正常窗口尺寸下视觉风格统一，首屏启动和多数计算响应也足够快。

但当前仍有一组会破坏工程可信度的 P0 问题：多个安全系数阈值和载荷放大系数只校验 `> 0`，没有校验其工程下界 `>= 1`；赫兹、过盈、蜗轮和缓冲块的若干标量输入未统一拒绝 `NaN/Inf`；螺栓自动柔度模型允许负截面积；轴向受力螺纹页的强度等级与 `Rp0.2` 没有联动。这些问题均已通过当前代码运行探针复现，其中多项可以把本应失败的工况变成 `PASS`。

因此当前版本应被定义为：

- 计算与工作流：**可用于预校核和研发验证，但需要先关闭 P0 输入域漏洞**。
- UI：**正常尺寸下达到一致、可用，尚未达到高品质商业工程软件的精修水平**。
- 性能：**首屏和计算无明显瓶颈；蜗轮页面首次打开和全页面内存仍有优化空间**。
- 架构：**核心/UI 分层方向正确，但大页面、重复字段协议和重复校验器已形成明显维护风险**。
- 发布工程：**测试基础好，但缺少锁定依赖、CI 和真实打包 smoke gate**。

## 3. 现有优势

1. `core/` 保持纯 Python，不依赖 Qt，计算层和 UI 层的大方向正确。
2. 主窗口采用页面懒构造，首屏没有一次性加载所有重模块，见 `app/ui/main_window.py:91-113`。
3. 输入改变后会使旧结果和导出失效；渲染失败和报告失败路径已有专门测试。
4. 输入条件文件带模块标签校验，根对象和模块错配会被拒绝，见 `app/ui/input_condition_store.py:25-44`。
5. `tests/ui/test_field_mapping_contract.py` 对 6 个字段型页面执行默认 payload 到 core 的接线合同测试。
6. 历史高风险问题已有大量回归保护，包括三态总体结论、空心轴内孔壁、蜗轮接触曲率一致性、输入变更后的导出失效等。
7. 统一暖中性主题、卡片结构、结果状态条和页面骨架已经形成稳定的产品语言。

## 4. 严重程度定义

- **P0 / Critical**：可能产生虚假 PASS、非物理计算或材料/规格错配；阻止可信发布。
- **P1 / Important**：高概率误导用户、破坏支持窗口、数据合同或关键工作流；应在品质版前完成。
- **P2 / Quality**：维护性、性能、视觉一致性、可访问性和发布工程问题；不一定立即算错，但会持续增加风险。
- **P3 / Evolution**：模型深化、标准覆盖、专业数据库和长期产品能力。

## 5. 计算逻辑、输入逻辑与自动化 Review

### [P0] CALC-01 安全阈值小于 1 时可把危险工况变成 PASS

证据：

- 蜗轮接触/齿根目标安全系数只做正值校验：`core/worm/calculator.py:465-472`。
- 花键齿面安全下限只做正值校验：`core/spline/calculator.py:245-247`。
- 螺栓和轴向螺纹的脱扣目标安全系数只做正值校验：`core/bolt/calculator.py:563-567`、`core/bolt/tapped_axial_joint.py:281-294`。
- 上述字段均可从 UI 编辑，例如 `app/ui/pages/worm_gear_page.py:213-214`、`app/ui/pages/bolt_page.py:860-866`。

运行探针：

- `worm_case_01` 的接触/齿根安全系数约为 `0.0636 / 0.1919`，默认失败；把两个目标安全系数改为 `0.01` 后总体变为 `PASS`。
- 花键工况 `torque=300 N·m`，安全系数约 `0.6288`，默认失败；把下限改为 `0.1` 后总体变为 `PASS`。
- 轴向螺纹脱扣安全系数约 `0.0521`；目标值从 `1.25` 改为 `0.01` 后总体从失败变为通过。

影响：总体状态失去工程语义，属于直接的虚假绿色结论。

要求：所有“安全系数下限”在 core 强制 `>= 1.0`；UI 只允许合规范围，并给出推荐范围与自定义值警告。

### [P0] CALC-02 载荷/应用放大系数小于 1 时可系统性低估载荷

证据：

- 花键 `KA`：`core/spline/calculator.py:242-243`。
- 过盈 `KA`：`core/interference/calculator.py:179-187`。
- 蜗轮应用系数、动载系数、横向/齿宽载荷系数：`core/worm/calculator.py:100-105`、`448-455`。
- UI 文案把这些字段描述为载荷放大/工况系数，推荐范围从 1 开始，但 core 只要求正数。

运行探针：

- 花键 `torque=300 N·m`：`KA=1` 时失败、安全系数约 `0.7861`；`KA=0.1` 时通过、安全系数约 `7.8606`。
- `interference_case_01` 将扭矩改为 `200 N·m`：`KA=1` 时滑移安全系数约 `1.1656`，低于要求；`KA=0.1` 后总体通过。
- `worm_case_01` 在目标安全系数为 1 时，`KA=1` 失败；`KA=0.001` 后总体通过。

影响：用户只需输入一个看似合法的正数，即可获得低估后的载荷和虚假 PASS。

要求：将工程定义为放大/分布的系数统一限定 `>= 1.0`；若确需减载系数，应使用另一个有清晰物理含义的字段，不能复用 `KA/KV/KH*`。

### [P0] CALC-03 非有限数没有统一拒绝，部分可形成虚假 PASS

证据：

- 赫兹、过盈、蜗轮、缓冲块的 `_positive()` 没有 `math.isfinite()`：`core/hertz/calculator.py:19-24`、`core/interference/calculator.py:19-24`、`core/worm/calculator.py:25-30`、`core/buffer/calculator.py:30-35`。
- 螺栓与花键已有有限数转换，说明不同模块合同已经漂移。

运行探针：

- 赫兹 `allowable_p0_mpa=inf` 返回 `overall_pass=True`、安全系数为 `inf`。
- 过盈轴/轮毂屈服强度设为 `inf` 可返回无限安全系数和总体通过。
- 蜗轮许用接触/齿根应力设为 `inf` 可使负载能力总体通过。
- 缓冲块 `available_stroke_mm=inf` 或 `allowable_peak_force_n=inf` 均返回总体通过。

影响：从直接 core/CLI、异常 JSON、程序化集成或没有正则过滤的页面路径进入时，`NaN/Inf` 会污染结果甚至给绿灯。

要求：所有标量进入公式前通过同一个 `to_finite_float()`；JSON 输入和 UI 构建 payload 后再做一次 core 级防线。

### [P0] CALC-04 螺栓自动柔度模型接受负有效截面积

证据：

- 圆柱模型直接计算 `D_A²-d_h²`，没有要求 `D_A>d_h`：`core/bolt/compliance_model.py:65-72`。
- 套筒模型同样没有要求 `D_outer>D_inner`：`core/bolt/compliance_model.py:97-104`。
- `_resolve_compliance()` 接收自动模型返回的负 `delta_p` 后不再次做正值检查：`core/bolt/calculator.py:74-125`。
- 后续只拒绝 `phi_n>=1`，不拒绝 `phi_n<=0`：`core/bolt/calculator.py:304-310`。

运行探针：

- `d_h=12, D_A=10` 的圆柱模型返回 `A_p=-34.5575 mm²`、`delta_p=-2.7559e-6 mm/N`。
- `D_outer=10, D_inner=12` 的套筒模型返回相同负面积和负柔度。
- 把示例自动模型 `D_A` 设为 `5 mm` 后，完整 calculator 接受输入并产生 `phi=-1.2907`，继续输出总体结果。

影响：非物理刚度进入载荷分配、预紧和热损失链路；结果即使最终为 FAIL，也不能被信任。

要求：几何函数在算式前验证外径大于内径；所有模型输出统一断言 `delta_s>0`、`delta_p>0`、`0<phi_n<1`。

### [P0] INPUT-01 轴向螺纹强度等级与屈服强度未接线

证据：

- 页面同时提供 `Rp0.2` 和强度等级 8.8/10.9/12.9：`app/ui/pages/bolt_tapped_axial_page.py:108-119`。
- 页面只对 `d/p` 派生尺寸做自动联动：`app/ui/pages/bolt_tapped_axial_page.py:630-656`；没有 grade 变化处理。

UI 运行探针：

- 初始 `8.8 / 640 MPa`。
- 切换到 `10.9` 或 `12.9` 后，`Rp0.2` 仍为 `640 MPa`，字段仍可编辑；payload 分别成为 `grade=10.9/Rp02=640` 和 `grade=12.9/Rp02=640`。

影响：规格标签和真正参与强度校核的数值可互相矛盾，报告追溯信息会给人错误信心。

要求：预设强度等级是单一事实源，自动填充并锁定 `Rp0.2`；另设“自定义材料”选项才允许手填，并在报告中明确来源。

### [P1] CONTRACT-01 calculator 根对象和模式枚举没有统一验证

证据：

- 赫兹、过盈、蜗轮、花键传入 `[]` 时产生原始 `AttributeError: list has no attribute get`，不是模块 `InputError`。
- 缓冲块已显式要求 dict：`core/buffer/calculator.py:381-382`。
- 花键 `mode` 在 `core/spline/calculator.py:233` 读取后只判断是否等于 `combined`；拼写错误会静默退化为 `spline_only`。

影响：CLI/API 集成无法稳定处理错误；错误的组合校核请求可能被静默降级，只返回场景 A。

要求：所有公开 calculator 首行校验 dict；所有枚举采用显式白名单并拒绝未知值。

### [P1] INPUT-02 缺少统一的字段约束与即时反馈

证据：全仓 UI 没有 `QDoubleValidator/QIntValidator/setValidator`；各页面独立解析字符串，在执行计算后才集中报错。7 个模块约有 242 个字段定义，约束、显示、payload、帮助和默认值分散在页面类中。

影响：

- 用户不能在输入时知道边界、单位和非法原因。
- UI 和 core 合法域容易漂移，本轮 P0 就是直接例证。
- 同一类错误在不同模块有不同消息和行为。

要求：建立共享字段 schema，至少包含类型、是否有限、最小/最大值、最小值是否包含、枚举、单位、来源、只读/派生、条件必填；UI 做即时提示，core 仍做最终校验。

### [P1] AUTO-01 自动化程度不均衡

已做得较好：

- 主螺栓页的规格/等级、部分材料、柔度与装配推荐有联动。
- 轴向螺纹 `d/p → d2/d3/As` 自动派生并只读。
- 过盈配合、蜗轮、赫兹提供部分材料自动填充。

仍需提升：

- 轴向螺纹 grade 与 `Rp0.2` 未联动。
- 赫兹材料只自动填 E/ν，许用接触应力仍完全手填；材料来源、热处理和循环寿命没有形成可追溯推荐链。
- 蜗轮材料自动填值与 Method B 简化能力之间缺少明确的“来源/适用范围/是否用户覆盖”状态。
- 过盈、花键的安全系数和应用系数没有按工况类型提供受控推荐。
- 计算结果没有统一的“输入来源清单”：用户输入、标准派生、目录值、经验默认和计算派生应能区分。

建议：先修数据合同，再增加自动化；不应通过更多隐式默认值掩盖不确定性。

### [P1] MODEL-01 赫兹接触范围描述不足

核心使用两个正曲率倒数相加，页面文案描述圆柱-圆柱/球-球，但没有明确“外接触、同号凸曲率”限制。当前不支持内接触的负曲率约定，也没有在 UI 和报告中声明这一边界。

要求：首版至少明确只支持外接触；若扩展内接触，需定义有符号曲率、几何合法域和独立基准样例。

### [P1] MODEL-02 简化/经验模型需要更强的证据分级

- 过盈计算仍含来源不可追溯、由回归锁定的经验系数，见 `core/interference/calculator.py:326-328`、`409-411`。
- 蜗轮明确是 Method B 风格最小子集，不是完整 DIN 3996。
- 花键是 DIN 5480 / DIN 6892 风格预校核，不是签发计算。

要求：结果页和导出报告把“正式校核、简化预校核、参考估算、未校核”做成结构化等级，不能只靠说明段落。

## 6. UI、视觉与交互 Review

### 总体评价

正常 `1400×860` 下，暖中性配色、卡片圆角、按钮高度、导航和结果状态语言较统一，已经具有产品化基础。主要差距不在“有没有样式”，而在支持尺寸、信息层级、细节一致性、可访问性和结果语义精修。

### [P1] UI-01 当前声明最小尺寸不可用

证据：

- 主窗口声明最小尺寸 `900×620`：`app/ui/main_window.py:66-68`。
- 侧栏只设最小宽度 `160`：`app/ui/main_window.py:218-224`。
- 在 `900×620` offscreen 渲染中，模块列表出现约 52 px 的水平滚动范围；品牌截断为 `Engineering As...`。
- 多个页面“保存输入条件/加载输入条件/导出结果说明”按钮被压缩成残缺文本。
- 轴向螺纹和花键的章节列表产生水平滚动；蜗轮/赫兹的标题和侧栏项出现截断。

影响：软件自己允许用户缩到一个无法完整识别按钮和模块名称的尺寸，不符合高品质桌面应用标准。

要求：二选一并形成明确契约：

1. 将最小支持尺寸提高到实际不截断的尺寸；或
2. 实现响应式侧栏折叠、动作菜单和弹性标题。

验收时支持尺寸内不得出现非内容型水平滚动条、关键按钮截字或品牌截断。

### [P1] UI-02 结果语言和状态层级不统一

观察：

- 花键使用 `PRECHECK PASS/FAIL`，蜗轮使用 `Load Capacity`，其他模块主要为中文。
- 过盈结果区暴露 `fit source / fit name` 等英文追踪行。
- 轴向螺纹混用 `von Mises`、原始变量名和英文 option 值。
- 多个页面同时在结果卡和页脚重复总体状态，信息优先级不清晰。
- “正式校核失败”“参考估算超限”“模型范围警告”常使用相似红色视觉权重。

影响：用户难以一眼区分结论级别、警告和追踪信息，降低工程报告的专业感。

要求：统一中文主标签；英文符号作为副标签；统一 `通过/不通过/校核不完整/未校核/仅参考` 五类语义；参考项不得影响正式总状态，也不得与正式失败同权。

### [P1] UI-03 输入页和结果页信息密度不平衡

观察：

- 简介/首章节有大量空白，而完整结果页堆叠长段等宽文本和多层卡片。
- 字段下方帮助、卡片 subtitle、tooltip 和底部说明存在重复。
- 按钮条在窄宽度下仍保持全部平铺，未区分主操作与次操作。
- 缓冲块页面同时使用“导入曲线文件”和“执行仿真”两个强强调按钮，主路径不够明确。

要求：结果采用“总体结论 → 关键指标 → 分项检查 → 追溯/公式”逐级展开；次要动作进入更多菜单；帮助只保留一个主入口并支持就地错误提示。

### [P1] UI-04 16×16 帮助按钮点击目标过小

证据：`app/ui/theme.py:764-775` 把帮助按钮宽高固定为 16 px。

影响：鼠标命中、触控板操作、低视力用户和高 DPI 环境体验不足；视觉上也显得琐碎。

要求：图标可保持 14–16 px，但交互 hit area 至少 28×28 px，推荐 32×32 px；有可见 focus ring 和键盘访问。

### [P2] UI-05 全局 monkey patch QComboBox 风险较高

证据：`app/ui/theme.py:31-96` 全局替换 `QComboBox.__init__` 与 `showPopup`。

影响：所有第三方或未来页面组合框都被隐式改变；平台升级后容易出现首开、窗口 flag、焦点和原生 popup 回归。宽度调整还发生在 `original_show()` 之后，首次 popup 的几何需要前景验证。

要求：封装为应用自有 ComboBox/代理样式，或至少集中安装、版本防护并增加 macOS/Windows 前景 smoke。

### [P2] UI-06 字体回退造成告警和额外延迟

offscreen 探针观察到不存在的 `Sans Serif` 和 `Consolas` 引发 Qt 字体别名填充，单次约 57–62 ms。`bolt_flowchart.py:351` 已把 Menlo 放在 Consolas 前，但其他路径仍需统一检查。

要求：通过 `app/ui/fonts.py` 提供平台字体栈和 monospace 选择，不在页面写死字体族。

### 光学对齐结论

正常尺寸下大多数卡片边界和字段列几何一致，但还没有达到“逐像素光学校准”的证据标准。本轮没有对所有页面做前景角点、基线和 icon optical center 测量。进入 UI 精修阶段后应形成截图矩阵，检查：标题基线、图标视觉中心、按钮文字重心、卡片内边距、状态胶囊、单位列、圆角像素、focus/hover/disabled 四态。

## 7. 启动、加载、运行速度 Review

### 测量结果

独立 offscreen 进程的重复测量范围：

| 项目 | 当前测量 |
|---|---:|
| `PySide6` import | 约 52–70 ms |
| 主题应用 | 约 7 ms |
| `MainWindow` 构造（含首个螺栓页） | 约 220–229 ms |
| 首次 paint | 约 15 ms |
| 首屏 RSS | 约 125 MB |
| 轴向螺纹页首次构造 | 约 45–49 ms |
| 过盈页首次构造 | 约 102–111 ms |
| 花键页首次构造 | 约 63–66 ms |
| 蜗轮页首次构造 | 约 248–253 ms |
| 赫兹页首次构造 | 约 39–41 ms |
| 缓冲块页首次构造 | 约 34–36 ms |
| 全部页面构造后 RSS | 约 222 MB |

样例计算加结果渲染：螺栓约 13 ms、轴向螺纹约 7 ms、过盈约 11 ms、花键约 3 ms、蜗轮约 37 ms、赫兹约 5 ms、缓冲块约 5 ms。

### 结论

- 首屏启动和所有计算均没有当前性能阻塞。
- 主窗口懒加载有效，是应保留的架构优点。
- 蜗轮页面首次进入明显慢于其他页面，主要因为页面构造时创建 matplotlib 图表，见 `app/ui/widgets/worm_stress_curve.py:15-39`。
- 全部页面构造后内存增加约 97 MB；对本地桌面工具可接受，但可通过更细粒度图表懒加载降低。
- `MainWindow.modules` 属性会强制构造全部页面，见 `app/ui/main_window.py:164-176`；测试或扩展代码误用会绕过懒加载收益。

### [P2] PERF-01 蜗轮图表应延迟到真正可见或首次有数据时

建议：蜗轮页先使用轻量占位；进入应力曲线章节或第一次计算后再 import matplotlib 和创建 canvas。目标是蜗轮页首次导航低于 150–180 ms，并减少未使用图表时的内存。

### [P2] PERF-02 需要真实打包冷启动基线

源码 offscreen 数据不能代替 Windows PyInstaller 冷启动。发布 gate 应记录：首次/二次启动、杀毒扫描影响、主窗口可交互时间、首个计算、第一次 PDF 导出。

## 9. 测试覆盖 Review

测试数量和速度是当前明显优势，但 P0 能在 909 项测试全绿时存在，说明缺口集中在“属性/边界合同”而不是快乐路径。

必须新增的测试族：

1. 所有 calculator 的根对象、section 类型、枚举、`NaN/Inf` 参数化测试。
2. 所有安全下限和载荷放大系数的 `<1 / =1 / >1` 边界矩阵。
3. 几何关系属性测试：外径>内径、`0<phi_n<1`、面积/柔度/刚度为正且有限。
4. UI 自动联动合同：grade/material/fit/mode 改变后，所有受影响字段和 payload 同步。
5. “不能通过降低门槛得到 PASS”的变形测试。
6. 最小支持尺寸截图/几何测试：无关键截字、无横向滚动、按钮 hit area 达标。
7. Windows 打包 smoke：启动、加载样例、计算、保存输入、导出 PDF/DOCX/TXT。
8. 每个工程模型至少一个独立来源的基准样例，不只使用当前 calculator 生成期望值。
